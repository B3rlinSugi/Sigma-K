# ADR-009: Cabinet Relational & Historical Lineage Model

- **Status:** APPROVED
- **Date:** 2026-08-25
- **Deciders:** Berlin (Lead Software Architect), Ikhsan (Data Analyst), Pak Sigit (Mentor Lead Data Analyst)

## Context
Sistem legacy menyimpan relasi kabinet sebagai string teks `list_id_kl = "1,4,12"`. SIGMA-K harus memetakan keanggotaan kabinet secara relasional dan melacak silsilah kementerian (pemecahan, merger, nomenklatur baru).

## Decision
Menetapkan relasi relasional ternormalisasi: **`Cabinet` (1:N) `CabinetPeriod` (1:N) `CabinetMembership` (N:1) `Institution`** ditambah tabel silsilah **`InstitutionLineage`**.

## Alternatives Considered
- *Mempertahankan Format String Legacy:* Ditolak mutlak karena merusak kaidah normalisasi database (1NF) dan tidak dapat di-join secara relasional.

## Consequences
- **Positive:** Mampu menjawab kueri perbandingan antar-kabinet (misal Kabinet Indonesia Maju vs Kabinet Merah Putih) secara instan via SQL Join, integritas referensial foreign key terjamin.
- **Negative:** Diperlukan script migrasi untuk mem-parsing string `list_id_kl` legacy menjadi baris-baris membership.
