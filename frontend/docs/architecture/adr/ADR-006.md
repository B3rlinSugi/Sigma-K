# ADR-006: Authorization & Scoped Access Control

- **Status:** APPROVED
- **Date:** 2026-08-25
- **Deciders:** Berlin (Lead Software Architect), Kak Nabila (Mentor)

## Context
Sistem melayani berbagai kementerian/lembaga. Operator dari Kementerian A dilarang memanipulasi draf atau data Kementerian B (Mitigasi BOLA / IDOR).

## Decision
Menerapkan kombinasi **Role-Based Access Control (RBAC)** dan **Scope-Based Authorization Guard** di level middleware dan query repository.

## Alternatives Considered
- *RBAC Murni Tanpa Scoping:* Berbahaya karena operator instansi mana pun dapat mengedit instansi lain jika memiliki role USER yang sama.

## Consequences
- **Positive:** Isolasi mutlak data draf antar-kementerian, perlindungan terhadap eksploitasi parameter URL ID.
- **Negative:** Setiap endpoint mutasi wajib memasang decorator `@ScopedInstitution()`.
