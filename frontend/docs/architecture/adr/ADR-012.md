# ADR-012: Search Engine Strategy

- **Status:** APPROVED
- **Date:** 2026-08-25
- **Deciders:** Berlin (Lead Software Architect), Ikhsan (Data Analyst)

## Context
Sistem membutuhkan fitur pencarian instansi, unit organisasi, dan butir tugas & fungsi dengan kecepatan instan dan toleransi salah ketik (*fuzzy matching*).

## Decision
Memanfaatkan **PostgreSQL Native Full-Text Search (tsvector/tsquery) + `pg_trgm` (Trigram Similarity) dengan GIN Indexing**.

## Alternatives Considered
- *Elasticsearch / OpenSearch:* Ditolak karena volume data (~600 instansi, ~50.000 unit kerja) tidak membenarkan overhead komputasi dan kompleksitas cluster Elasticsearch.

## Consequences
- **Positive:** Nol biaya infrastruktur tambahan, konsistensi data transaksi seketika (ACID), pencarian sangat cepat ($< 10$ ms).
- **Negative:** Tidak memiliki fitur semantic NLP canggih, namun kebutuhan semantik diposisikan pada Future Scope (REQ-030).
